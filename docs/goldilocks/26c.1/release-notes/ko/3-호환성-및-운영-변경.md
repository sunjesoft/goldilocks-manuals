## 플랫폼·트랜잭션·서버 설정

### 릴리즈 플랫폼 변경

릴리즈 플랫폼에서 HP, AIX, PPC64가 제거되었다. 현재 매뉴얼의 릴리즈 플랫폼 표에는 서버용 linux-x86_64와 Linux·Windows 계열 클라이언트 플랫폼이 안내되어 있으므로 설치 대상에 맞는 패키지를 확인해야 한다.

관련 내용은 [릴리즈 플랫폼](../../ko/part-01-getting-started/2-튜토리얼.md#21ae4f5cc1938a2b)을 참조한다.

<a id="d84d816f149047cf"></a>
### 클러스터 SERIALIZABLE 지원 중단

클러스터 시스템에서 트랜잭션 격리 수준 SERIALIZABLE을 더 이상 지원하지 않는다. 클러스터 환경에서 SET TRANSACTION 또는 SET SESSION CHARACTERISTICS AS TRANSACTION으로 격리 수준을 설정할 때는 READ COMMITTED를 사용해야 한다. SET TRANSACTION 으로 설정한 격리 수준은 다음 트랜잭션에 적용되며, 해당 트랜잭션이 종료되면 기본 속성으로 복원된다.

관련 내용은 [SET TRANSACTION의 격리 수준](../../ko/part-03-sql-manual/20-sql-references-h-z.md#6244d814539b38cb), [SET SESSION CHARACTERISTICS](../../ko/part-03-sql-manual/20-sql-references-h-z.md#7d01dc0bb72bd9a4)의 격리 수준을 참조한다.

<a id="da3f1dc66a774c96"></a>
### DEFAULT_INDEX_PCTFREE 기본값

DEFAULT_INDEX_PCTFREE의 기본값이 10으로 변경되었다. 인덱스 생성 시 PCTFREE를 명시하지 않으면 이 프로퍼티 값이 적용된다. 따라서 기존 생성 스크립트에서 PCTFREE를 생략하는 경우에도 변경된 기본값인 10 이 적용된다.

관련 내용은 [DEFAULT_INDEX_PCTFREE](../../ko/part-02-administration-manual/10-server-property.md#a70319f95fa6c573)를 참조한다.

<a id="ef85dfd35068c63c"></a>
### DEFAULT_MAXTRANS 기본값

DEFAULT_MAXTRANS의 기본값이 32로 변경되었다. 테이블이나 인덱스 생성 시 MAXTRANS를 명시하지 않으면 이 프로퍼티 값이 적용된다.

관련 내용은 [DEFAULT_MAXTRANS](../../ko/part-02-administration-manual/10-server-property.md#38446e3a7bf4bd60)를 참조한다.

<a id="2dbaf67bf597437a"></a>
### BUFFER_DIRTY_PAGE_LIMIT 이름 및 기본값

INCREMENTAL_CHECKPOINT_CRITERIA의 이름이 BUFFER_DIRTY_PAGE_LIMIT로 변경되었으며, 기본값은 0으로 변경되었다. 기존 이름은 매뉴얼에서 alias로 안내하고 있다.

이 프로퍼티는 버퍼 캐시에서 갱신된 페이지 수를 기준으로 증분 체크포인트를 수행할 시점을 결정한다. 기본값인 0은 무한대를 의미하므로, 버퍼의 모든 페이지가 갱신되더라도 이 기준에 따른 증분 체크포인트는 수행되지 않는다.

관련 내용은 [BUFFER_DIRTY_PAGE_LIMIT](../../ko/part-02-administration-manual/10-server-property.md#141a470d8d601f73)를 참조한다.

<a id="820447085fc07bbe"></a>
### 클러스터 통신 버퍼 프로퍼티 변경

CLUSTER_CM_BUFFER_COUNT가 deprecated로 지정되었으며, 디스패처별 통신 버퍼 수를 설정하는 다음 프로퍼티가 추가되었다.

<a id="dec9f520481701e8"></a>
| 항목 | 설명 |
| --- | --- |
| `LOCKABLE_DISPATCHER_CM_BUFFER_COUNT` | lockable dispatcher의 통신 버퍼 수를 지정한다. |
| `LOCKLESS_DISPATCHER_CM_BUFFER_COUNT` | lockless dispatcher의 통신 버퍼 수를 지정한다. |
| `SYNC_DISPATCHER_CM_BUFFER_COUNT` | synchronization dispatcher의 통신 버퍼 수를 지정한다. |

각 프로퍼티의 기본값은 1이다. ALTER SESSION과 ALTER SYSTEM 을 통한 변경은 허용되지 않는다.

관련 내용은 [LOCKABLE_DISPATCHER_CM_BUFFER_COUNT](../../ko/part-02-administration-manual/10-server-property.md#6ea8fae775896cf8), [LOCKLESS_DISPATCHER_CM_BUFFER_COUNT](../../ko/part-02-administration-manual/10-server-property.md#4ddbc6e597502b57), [SYNC_DISPATCHER_CM_BUFFER_COUNT](../../ko/part-02-administration-manual/10-server-property.md#3e14bf273b75b9e8)를 참조한다.

<a id="9010b9db077a9ce2"></a>
### 플랜 캐시 제어 프로퍼티 통합

MAXIMUM_FLANGE_COUNT가 deprecated 로 지정되어 플랜 캐시는 PLAN_CACHE_SIZE 로만 제어한다. PLAN_CACHE_SIZE 는 플랜 캐시에 사용할 메모리 크기를 바이트 단위로 지정하는 프로퍼티다. 따라서 이 값을 SQL 문의 개수로 해석하지 않도록 주의해야 한다.

관련 내용은 [PLAN_CACHE_SIZE](../../ko/part-02-administration-manual/10-server-property.md#20b7c3ce69752590)를 참조한다.

<a id="9a3136a2820196c9"></a>
### PLAN_CACHE_SIZE 온라인 변경

PLAN_CACHE_SIZE를 서버 재시작 없이 온라인으로 변경할 수 있도록 개선되었다. 이 프로퍼티는 SQL 실행 계획 캐시에 사용할 메모리 크기를 지정한다. 세션 단위 변경은 허용되지 않으며, 시스템 단위 변경만 허용된다.

관련 내용은 [PLAN_CACHE_SIZE](../../ko/part-02-administration-manual/10-server-property.md#20b7c3ce69752590)를 참조한다.

<a id="0d3d09e3ce237a9b"></a>
### V$SQL_CACHE REF_COUNT 제거

V$SQL_CACHE에서 REF_COUNT column이 제거되었다. 이 view는 공유 SQL 실행 계획의 통계를 제공하며 SQL 텍스트, 계획 개수, 계획 크기와 계획 텍스트 등을 조회한다. REF_COUNT를 명시적으로 참조하던 모니터링 query는 변경된 column 목록에 맞게 수정해야 한다.

관련 내용은 [V$SQL_CACHE](../../ko/part-02-administration-manual/9-database-information.md#752ef279734cff3f)를 참조한다.

<a id="7c8b39916e4be05c"></a>
### AGING_PLAN_INTERVAL 기본값

AGING_PLAN_INTERVAL의 기본값이 0에서 3으로 변경되었다. 단위는 초이며, 지정된 시간보다 오래된 SQL plan이 aging 대상이 된다.

관련 내용은 [AGING_PLAN_INTERVAL](../../ko/part-02-administration-manual/10-server-property.md#057ca3b036d23605)을 참조한다.

<a id="5665919c340e58dc"></a>
### SESSION_MEMORY_INIT_SIZE 기본값

SESSION_MEMORY_INIT_SIZE의 기본값이 131072(128K)에서 524288(512K)로 변경되었다. 이 프로퍼티는 dedicated session에서 사용할 초기 메모리 크기를 지정한다.

관련 내용은 [SESSION_MEMORY_INIT_SIZE](../../ko/part-02-administration-manual/10-server-property.md#9d01096d9cfaec26)를 참조한다.

<a id="83057968f143ebb0"></a>
### 클러스터 TRANSACTION_TABLE_SIZE 제약 완화

클러스터의 모든 멤버가 동일한 TRANSACTION_TABLE_SIZE 값을 가져야 한다는 제약이 제거되었다. 각 멤버의 트랜잭션 테이블 크기를 변경하려면 데이터베이스를 재시작해야 한다.

설정값을 줄이려면 재시작 복구 이후 prepare 된 트랜잭션이 사용한 slot 식별자의 최대값보다 큰 값으로 설정해야 한다. 최대값 이하로 설정할 경우 재시작에 실패할 수 있다.

관련 내용은 [TRANSACTION_TABLE_SIZE](../../ko/part-02-administration-manual/10-server-property.md#e20fffefb153528b)를 참조한다.

<a id="65736d63b099c9d5"></a>
### 클러스터 데드락 검출 방식 변경

클러스터 자체 데드락 검출 기능이 도입됨에 따라 기존 CLUSTER_DEADLOCK_TIMEOUT 프로퍼티는 deprecated 되었다.

<a id="aa2f8c6e534cc7d4"></a>
### 클러스터 비동기 replica 적용 설정 변경

클러스터의 replica 반영 방식이 기본적으로 async replica 로 처리되도록 개선되었다. 해당 방식을 사용할 수 없는 환경에서는 시스템 내부에서 자동으로 처리하며, 기존 CLUSTER_ASYNC_REPLICATION 프로퍼티는 deprecate 되었다.

<a id="4ab1f8461ccd5aab"></a>
### SHARED_MEMORY_STATIC_SIZE 기본값

SHARED_MEMORY_STATIC_SIZE 프로퍼티의 기본값이 800M(838860800바이트)로 변경되었다. 이 프로퍼티는 Shared Static Area(SSA)의 크기를 지정하며, ALTER SESSION과 ALTER SYSTEM 구문으로 변경할 수 없는 속성이다.

관련 내용은 [SHARED_MEMORY_STATIC_SIZE](../../ko/part-02-administration-manual/10-server-property.md#eadde14e86afa8c7)를 참조한다.

### INST_TABLE_PAGE_SIZE 이름 변경

INST_TABLE_BLOCK_SIZE 프로퍼티의 이름이 INST_TABLE_PAGE_SIZE로 변경되었다. 기존 이름은 alias로 계속 지원된다. 이 프로퍼티는 인스턴트 테이블의 페이지 크기를 결정한다. 인스턴트 레코드의 고정 영역이 지정된 페이지 크기를 초과할 경우 최대 레코드 길이 오류가 발생할 수 있다.

<a id="8925476cd6ae98f8"></a>
### 클러스터 commit 통신 분리

클러스터의 commit 관련 프로토콜이 별도의 dispatcher와 queue를 사용하도록 분리 개선되었다. 이에 따라 기존 CLUSTER_COMMIT_STREAM_ISOLATION 프로퍼티는 deprecate 되었다.

운영 상태는 V$CLUSTER_DISPATCHER view에서 dispatcher 유형과 송수신 통계로 조회할 수 있으며, TYPE column에는 commit 항목이 포함된다. 클러스터 queue 목록과 적재 건수는 V$CLUSTER_QUEUE view에서 확인할 수 있다.

관련 내용은 [V$CLUSTER_DISPATCHER](../../ko/part-02-administration-manual/9-database-information.md#d2b23c79ecd3a287), [V$CLUSTER_QUEUE](../../ko/part-02-administration-manual/9-database-information.md#cb1d377a01eb9832)를 참조한다.

### 온라인 DDL 프로퍼티 이름 변경

온라인 DDL 관련 프로퍼티 이름이 다음과 같이 변경되었다. 기존 프로퍼티 이름은 하위 호환성을 위해 alias로 지원된다.

<a id="6b419af263f2acd0"></a>
| 기존 이름 | 변경된 이름 | 용도 |
| --- | --- | --- |
| REBALANCE_BLOCK_READ_COUNT | ONLINE_DDL_BLOCK_READ_COUNT | 원격 전송 단위인 block에 포함할 레코드 수를 지정한다. |
| REBALANCE_SHARD_DIVISOR | ONLINE_DDL_SCAN_PARTITION | Online DDL 실행 시 shard를 분할하여 동기화할 개수를 지정한다. |

| ONLINE_JOURNAL_REPLAY_THRESHOLD | ONLINE_DDL_JOURNAL_REPLAY_THRESHOLD | 남은 journal log 양이 적을 때 EXCLUSIVE lock을 획득하여 마지막 반영 단계로 전환하는 임계값을 지정한다. |

### ALTER INDEX COALESCE 동시 실행 제한

ALTER INDEX COALESCE는 다른 ALTER 구문과 동시에 실행할 수 없도록 변경되었다. 22c.1에서 동시에 수행하던 관리 작업이 있다면 실행 순서를 조정해야 한다.

COALESCE는 인접한 인덱스 leaf page를 병합하여 사용 공간을 확보하는 작업이다. DML과 동시 실행은 기존과 동일하게 지원되며, 이번 제한 사항은 다른 ALTER 구문과의 동시 실행에만 적용된다.

관련 내용은 [ALTER INDEX name COALESCE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#ba3aecf4b34c844b)를 참조한다.

<a id="4584d213bf54be05"></a>
### ADD CONSTRAINT ON SCHEMA 권한 제거

ADD CONSTRAINT ON SCHEMA 권한이 제거되었다. 테이블 소유자의 경우 CREATE TABLE 시 자동으로 부여된 ALTER ON TABLE 권한을 사용하여 제약 조건을 추가한다. 비소유자의 경우 대상 테이블에 대한 ALTER ON TABLE 또는 ALTER TABLE ON SCHEMA 권한이 필요하다.

추가된 제약 조건의 소유자는 테이블 소유자가 된다.

관련 내용은 [ALTER TABLE name ADD CONSTRAINT](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b1bf02c95ebfb66d)를 참조한다.

<a id="043f9ad8f72b9281"></a>
### 신규 사용자의 기본 schema path 변경

CREATE USER 구문으로 사용자를 생성할 때 기본 적용되는 user schema path에서 PUBLIC 스키마가 제외되도록 변경되었다. 이제 사용자의 전용 스키마만 기본 검색 경로로 지정되므로, 22c.1 이하 버전과 동일한 검색 경로가 필요할 경우 사용자 스키마 뒤에 PUBLIC을 명시적으로 설정해야 한다.

```
ALTER USER u1 SCHEMA PATH (u1, public);
```

스키마 이름을 생략한 객체 참조는 schema path 를 기준으로 해석한다. 단, WITHOUT SCHEMA 옵션으로 생성한 사용자의 기본 경로는 PUBLIC으로 설정된다.

관련 내용은 [CREATE USER의 schema 지정](../../ko/part-03-sql-manual/19-sql-references-c-g.md#d5a445948883221f), [Schema path 변경](../../ko/part-03-sql-manual/13-sql-objects.md#3d5355367b16fe83)을 참조한다.

### Online DDL의 shard divisor 이름 변경

Online DDL에서 사용하던 shard divisor 옵션의 이름이 scan partition으로 변경되었다. 기존 DDL 스크립트는 현재 문법인 SCAN PARTITION integer를 사용하도록 수정해야 한다. 이 옵션은 재배치·동기화할 shard의 분할 수를 지정하며, 생략하면 ONLINE_DDL_SCAN_PARTITION 값을 따른다. 적용 대상 DDL은 다음과 같다.

- [ALTER DATABASE MOVE SHARD](../../ko/part-03-sql-manual/18-sql-references-a-b.md#4752ea45b3668af4)
- [ALTER DATABASE REBALANCE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#045abf2d149b6478)
- [ALTER DATABASE REBALANCE EXCLUDE CLUSTER GROUP](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b2d27be01aaaa9b7)
- [ALTER DATABASE SYNCHRONIZE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#1620340d3358eb5b)
- [ALTER TABLE name MOVE SHARD](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b64b6ca52ad7b811)

### ODBC SQL_LONG_VARIABLE_LENGTH_STRUCT 필드 역할 분리

ODBC 비표준 타입에 사용되는 SQL_LONG_VARIABLE_LENGTH_STRUCT의 필드 구성이 변경되었다. buf_len은 arr 버퍼의 용량을, len은 실제 데이터 길이를 나타내며, 단위는 모두 바이트이다.   
이 구조체는 SQL_C_LONGVARCHAR 와 SQL_C_LONGVARBINARY 에 사용된다. 응용 프로그램은 버퍼를 할당한 뒤 arr와 buf_len을 설정하고, 입력 데이터를 채운 뒤 실제 길이를 len에 설정하여 바인딩한다.

관련 내용은 [ODBC: SQL_C_LONGVARCHAR 바인딩 예](../../ko/part-05-developer-manual/34-odbc.md#bca8806d8d4944ea)를 참조한다.

### JDBC ALTERNATE_LOCATOR 연결 속성 이름 변경

### Embedded SQL GET CLUSTER_GROUP_ID 구문 이름 변경

Embedded SQL의 GET GROUPID 구문 이름이 GET CLUSTER_GROUP_ID로 변경되었다. EXEC SQL GET CLUSTER_GROUP_ID INTO :group_id 구문 뒤에 대상 SQL을 지정하여 global connection을 사용하는 클러스터 환경에서 해당 SQL의 group ID를 얻는다. 대상 SQL은 shard key가 설정된 테이블에 대한 DELETE, INSERT, SELECT, UPDATE 문이며, :group_id 변수에는 signed numeric 타입을 사용해야 한다. 대상 SQL은 실제로 실행되지 않고 prepare 상태로 캐시되며, 유효하지 않은 ID 값인 -1이 반환될 수 있다.

관련 내용은 [Embedded SQL: EXEC SQL GET CLUSTER_GROUP_ID INTO](../../ko/part-05-developer-manual/36-embedded-sql.md#163e323215bf60ca)를 참조한다.

### Embedded SQL LONG VARCHAR 구조체 필드 역할 분리

Embedded SQL에서 LONG VARCHAR를 표현하는 SQL_LONG_VARIABLE_LENGTH_STRUCT의 필드 구성이 변경되었다. buf_len은 arr 버퍼의 용량을, len은 실제 데이터 길이를 나타내며 단위는 모두 바이트이다. 응용 프로그램에서 arr의 메모리를 할당하고 buf_len을 설정한 뒤, 데이터의 실제 길이를 len에 설정해야 한다. 사용이 완료된 메모리는 응용 프로그램에서 직접 해제해야 한다.

관련 내용은 [Embedded SQL: LONG VARCHAR](../../ko/part-05-developer-manual/36-embedded-sql.md#6f9127f189a796e4)를 참조한다.

### Embedded SQL VARCHAR·VARBINARY 음수 길이 오류 처리 변경

### glocator 이중화 구성

glocator의 다중화 구성이 이중화 구성으로 변경되었다. 두 glocator는 시작 순서에 따라 master와 sub(substitute)로 구분된다. --sync 옵션을 사용하여 나중에 시작하는 sub와 먼저 시작한 master를 연결한다. 동기화 시 두 glocator의 데이터를 병합하며, 값이 다른 중복 데이터는 최근에 갱신된 데이터로 덮어쓴다.

관련 내용은 [glocator 이중화 구성](../../ko/part-06-utility-manual/51-glocator.md#198e23e6d7fd28c0)을 참조한다.

<a id="41bfd2e48e53a63e"></a>
### glocator sync 옵션의 인자 제거

glocator의 --sync 옵션에 지정하던 인자가 제거되었다. 이제 glocator --start --sync 형식으로 시작하며, configuration file 내에 ALTERNATE_LOCATOR가 미리 설정되어 있어야 한다.

관련 내용은 [glocator sync 옵션의 인자 제거](../../ko/part-06-utility-manual/51-glocator.md#9b6a64cefee9396a)를 참조한다.

<a id="65db212828ea2227"></a>
### gagent의 ALTERNATE_LOCATOR 설정 이름

gagent configuration property의 이름이 ALTERNATE_LOCATORS 에서 ALTERNATE_LOCATOR 로 변경되었다. [AGENT] 섹션에 alternate locator의 이름을 지정하며, 해당 이름의 섹션에 HOST와 PORT를 설정한다.

관련 내용은 [gagent의 ALTERNATE_LOCATOR 설정 이름](../../ko/part-06-utility-manual/52-gagent.md#6516869ff8ad95b4)을 참조한다.
