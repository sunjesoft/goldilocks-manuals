## 데이터베이스 관리 및 정보 조회

<a id="2c931bb56f6daafb"></a>
### 병렬 복구

병렬 복구 기능이 추가되었다. ALTER DATABASE RECOVER에서 PARALLEL을 사용하여 복구에 참여하는 slave thread 수를 지정할 수 있으며, 데이터베이스·데이터 파일·테이블스페이스 복구 및 불완전 복구에 사용할 수 있다. 온라인 로그와 archive 로그를 적용하여 데이터 파일을 복구한다.

Slave thread 수는 0~64 로 지정할 수 있다. 0 또는 NOPARALLEL을 지정하면 master thread만 사용한다. 병렬 복구 절 또는 PARALLEL의 수를 생략하면 RECOVERY_SLAVES 값을 따른다. 데이터베이스 전체 완전 복구는 MOUNT 상태와 ARCHIVELOG 모드에서 수행한다.

관련 내용은 [ALTER DATABASE RECOVER](../../ko/part-03-sql-manual/18-sql-references-a-b.md#233fbcf85decd22e), [recovery slaves clause](../../ko/part-03-sql-manual/18-sql-references-a-b.md#913cd8233d004d7e)를 참조한다.

<a id="7638f0ef072c135d"></a>
### 병렬 백업

병렬 백업 기능이 추가되었다. ALTER DATABASE BACKUP INCREMENTAL의 PARALLEL 절로 백업 thread 수를 지정할 수 있다. 지정 범위는 1~64이며, PARALLEL의 수를 생략하면 1로 설정되고, PARALLEL 절 자체를 생략하면 NOPARALLEL로 동작한다.

실제 병렬 처리 수는 대상 데이터 파일 수와 PIECE 수에 따라 제한된다. 지정한 병렬 수보다 데이터 파일이나 PIECE 수가 적으면 해당 개수만큼 병렬 처리한다.

관련 내용은 [ALTER DATABASE BACKUP](../../ko/part-03-sql-manual/18-sql-references-a-b.md#93565f80d30924b0), [parallel clause](../../ko/part-03-sql-manual/18-sql-references-a-b.md#e51ae2ca49f251a0)를 참조한다.

<a id="3042f41e308d065d"></a>
### 병렬 복원

병렬 복원 기능이 추가되었다. ALTER DATABASE RESTORE 및 테이블스페이스 복원 구문에서 PARALLEL 을 사용하여 thread 수를 지정하고, 증분 백업의 데이터 파일을 복원할 수 있다. 데이터베이스 전체 복원은 MOUNT 상태에서 수행한다.

병렬 수는 1~64 지정할 수 있으며, PARALLEL의 수를 생략하면 1로 설정된다. PARALLEL 절 자체를 생략하면 NOPARALLEL로 동작한다.

관련 내용은 [ALTER DATABASE RESTORE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#60ea018060bd0c35), [parallel clause](../../ko/part-03-sql-manual/18-sql-references-a-b.md#ff382b76e4c0cf47)를 참조한다.

### RECOVERY_SLAVES

병렬 복구에 참여하는 slave thread 수를 제어하는 RECOVERY_SLAVES 프로퍼티가 추가되었다. 기본값은 8이며, 0으로 설정하면 slave thread 없이 master thread만 사용하여 복구한다. ALTER DATABASE RECOVER에서 병렬 복구 절 또는 PARALLEL의 수를 생략하면 RECOVERY_SLAVES 에 설정된 값을 사용한다.

<a id="7b8202f4ef29509a"></a>
### ANALYZE Sampling의 성능 및 정확도 개선

ANALYZE sampling에 repeatable random sampling, approximate NUM_DISTINCT (hyper log 알고리즘), exponent 곡선에 의한 NUM_DISTINCT 보정이 도입되었다. 예를 들어, 10% sampling을 사용하면 TPC-H 22개 질의에서 전수 ANALYZE와 동일한 실행 계획을 얻을 수 있다.

ANALYZE TABLE의 ESTIMATE STATISTICS에서 샘플링할 행 수 또는 비율을 지정할 수 있다. SAMPLE percentage PERCENT의 비율은 1~99의 정수이며, 샘플 행 수가 MIN_SAMPLE_ROW_COUNT보다 작으면 해당 프로퍼티 값을 따른다.

관련 내용은 [ESTIMATE STATISTICS](../../ko/part-03-sql-manual/18-sql-references-a-b.md#de6042db19449aa3)를 참조한다.

### Change Tracking 파일 이름 변경

ALTER DATABASE RENAME CHANGE TRACKING FILE 구문이 추가되었다. Change tracking 파일의 새 이름을 지정할 수 있으며, 데이터베이스가 MOUNT 상태이고 change tracking이 활성화되어 있어야 한다. 실행에는 ALTER DATABASE ON DATABASE 권한이 필요하다. 파일 이름에 절대 경로를 지정하지 않으면 SYSTEM_TABLESPACE_DIR와 결합한 경로를 사용한다.

관련 내용은 [ALTER DATABASE RENAME CHANGE TRACKING FILE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#86093b65db0319c4)을 참조한다.

<a id="797d84885c6314c7"></a>
### CHECK 제약 조건

CHECK 제약 조건이 추가되었다. CREATE TABLE, ALTER TABLE name ADD COLUMN, ALTER TABLE name ADD CONSTRAINT에서 각 row가 만족해야 하는 논리식을 정의한다. 조건 결과가 FALSE이면 위반으로 처리하고, TRUE 또는 UNKNOWN이면 조건을 만족하는 것으로 처리한다.

조건에는 subquery, 다른 객체 참조, 비결정적 표현식, pseudo column을 사용할 수 없으며, 참조 column 수는 최대 32개이다. NULL 허용 여부까지 제한하려면 UNKNOWN 처리 규칙을 고려해야 한다.

관련 내용은 [CHECK 제약 조건](../../ko/part-03-sql-manual/19-sql-references-c-g.md#9d54718478517ebd), [CREATE TABLE](../../ko/part-03-sql-manual/19-sql-references-c-g.md#ce6ecbcf1ea593ea), [ALTER TABLE name ADD COLUMN](../../ko/part-03-sql-manual/18-sql-references-a-b.md#5bf457087cd2404f), [ALTER TABLE name ADD CONSTRAINT](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b1bf02c95ebfb66d)를 참조한다.

<a id="b0eaedcc75bfd6e1"></a>
### FOREIGN KEY 제약 조건

FOREIGN KEY 제약 조건이 추가되었다. CREATE TABLE, ALTER TABLE name ADD COLUMN, ALTER TABLE name ADD CONSTRAINT에서 참조 관계를 정의한다. 외래 키 값은 참조 대상의 PRIMARY KEY 또는 UNIQUE 제약 조건에 존재해야 한다. 단, 외래 키에 NULL이 포함된 경우에는 예외적으로 허용된다.

Column 제약 조건에는 REFERENCES, 테이블 제약 조건에는 FOREIGN KEY (...) REFERENCES 형태를 사용한다. 외래 키를 정의하는 테이블은 base table이어야 하며 temp table과 view에는 정의할 수 없다.

관련 내용은 [FOREIGN KEY 제약 조건](../../ko/part-03-sql-manual/19-sql-references-c-g.md#254ccdad9ba898ff), [CREATE TABLE](../../ko/part-03-sql-manual/19-sql-references-c-g.md#ce6ecbcf1ea593ea), [ALTER TABLE name ADD COLUMN](../../ko/part-03-sql-manual/18-sql-references-a-b.md#5bf457087cd2404f), [ALTER TABLE name ADD CONSTRAINT](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b1bf02c95ebfb66d)를 참조한다.

<a id="fbe4139eaa7278b1"></a>
### 제약 조건 활성화 및 비활성화

제약 조건의 활성화 여부를 변경하는 constraint enforcement 옵션을 ALTER TABLE name ALTER CONSTRAINT에서 사용할 수 있게 되었다. ENFORCED는 제약 조건을 활성화하고 NOT ENFORCED는 비활성화한다. 변경할 제약 조건은 제약 조건 이름으로 지정하거나, PRIMARY KEY 또는 column 목록에 대응하는 UNIQUE 제약 조건으로 지정한다.

관련 내용은 [ALTER TABLE name ALTER CONSTRAINT](../../ko/part-03-sql-manual/18-sql-references-a-b.md#75005eef58445700)를 참조한다.

<a id="dc59ac29d9f48151"></a>
### 인덱스 활성화 및 비활성화

index enforcement를 제어하는 ALTER INDEX name ENABLE/DISABLE이 추가되었다. ENABLE은 인덱스를 구축하고 활성화하며, DISABLE은 인덱스를 비활성화하고 사용하던 extent를 모두 반납한다. 비활성화된 인덱스는 DML과 SELECT에서 사용하지 않는다.

ENABLE과 ENFORCED, DISABLE과 NOT ENFORCED는 각각 동일한 동작을 수행한다. Key 제약 조건을 위해 생성된 인덱스는 ALTER CONSTRAINT로 관리해야 한다.

관련 내용은 [ALTER INDEX name ENABLE/DISABLE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#8c8f90f0415b3a2e)을 참조한다.

<a id="ab411fae1f248dde"></a>
### 테이블 트리거 실행 순서 지정

ALTER TABLE name SET TRIGGER ORDER가 추가되었다. 테이블에 정의된 트리거 이름을 원하는 순서로 재배열하여 실행 순서를 바꾼다. 일부 트리거만 지정하면 해당 트리거를 지정한 순서대로 먼저 실행하고 나머지 트리거는 기존 순서를 유지한다. 나열한 트리거는 같은 테이블에 속하며 BEFORE/AFTER 시점과 ROW/STATEMENT 실행 단위가 같아야 한다.

관련 내용은 [ALTER TABLE name SET TRIGGER ORDER](../../ko/part-03-sql-manual/18-sql-references-a-b.md#e99539acedd7cb13)를 참조한다.

<a id="f76d8aac682fdeeb"></a>
### ALTER TABLE name REORGANIZE

테이블을 물리적으로 재구성하는 ALTER TABLE name REORGANIZE가 추가되었다. ONLINE에서는 INSERT·UPDATE·DELETE를 허용하고 OFFLINE에서는 허용하지 않으며, 기본값은 ONLINE이다. SCAN PARTITION과 PARALLEL로 분할·병렬 처리 옵션을 지정할 수 있다.

Redo log 기록의 기본값은 LOGGING이다. NOLOGGING을 사용하면 재구성 후 서버가 비정상 종료될 때 테이블이 unusable 상태가 될 수 있다. 따라서 NOLOGGING을 사용하는 경우 매뉴얼에 따라 재구성 후 CHECKPOINT를 실행해야 한다.

관련 내용은 [ALTER TABLE name REORGANIZE](../../ko/part-03-sql-manual/18-sql-references-a-b.md#b33b38d54cfadfd0)를 참조한다.

<a id="3496314a3b43e129"></a>
### MERGE

MERGE 구문이 추가되었다. USING으로 지정한 원본과 대상 테이블을 ON 조건으로 비교하여, 일치하면 UPDATE·DELETE·DO NOTHING, 일치하지 않으면 INSERT·DO NOTHING을 수행하도록 기술한다. 여러 변경 작업을 조건별로 한 구문에 표현할 수 있다.

각 대상 행은 WHEN 절을 작성한 순서대로 평가하며, 처음 참이 되는 분기만 실행한다. 별도의 MERGE 권한은 없으며, 참조 column에 대한 SELECT 권한과 구문에 명시한 INSERT·UPDATE·DELETE 작업에 필요한 권한이 필요하다.

관련 내용은 [MERGE](../../ko/part-03-sql-manual/20-sql-references-h-z.md#bc136bf193bf403b)를 참조한다.

<a id="763e31d419579b9a"></a>
### APPEND INSERT 및 힌트

APPEND INSERT 방식의 데이터 추가 기능과 이를 지정하는 힌트가 추가되었다. 사용하지 않은 공간이나 새로 할당한 공간에 데이터를 추가하여 대량 적재에 활용한다. 디스크 테이블은 버퍼를 거치지 않고 데이터 파일에 직접 기록한다.

INSERT의 APPEND 힌트, gloader의 관련 옵션 또는 특정 대량 동기화 DDL에서 사용할 수 있다. PARALLEL은 여러 세션의 동시 APPEND INSERT를 허용하고, 이 옵션과 함께 사용하는 NOLOGGING은 기록할 로그를 줄인다. STATEMENT_NOFORCE는 문장 완료 시 사용한 데이터 페이지의 디스크 반영 여부를 지정한다. 지정한 옵션에 따라 참조 무결성 검사나 인덱스 키 반영 여부가 달라질 수 있으므로 적재 방식에 맞는 옵션을 선택해야 한다.

관련 내용은 [APPEND INSERT 방식의 데이터 추가](../../ko/part-03-sql-manual/12-sql-languages.md#9fdab7fa44252736)를 참조한다.

<a id="5eefe452ac2220dc"></a>
### DELETE FROM의 local shard limit

DELETE FROM에 데이터 절체를 위한 local shard limit clause가 추가되었다. Cluster의 sharded table에서 local group에 있는 레코드를 지정한 limit_row_count 만큼 삭제한다. Sharded table 에서만 사용할 수 있으며 limit_row_count는 양수이어야 한다. result offset clause 및 fetch limit clause와 함께 사용할 수 없다.

관련 내용은 [local shard limit clause](../../ko/part-03-sql-manual/19-sql-references-c-g.md#d23d83f814803841)를 참조한다.

<a id="1affff8136c5c373"></a>
### GROUP BY의 ROLLUP·CUBE·GROUPING SETS

GROUP BY의 grouping element에 ROLLUP, CUBE, GROUPING SETS 지원이 추가되었다. ROLLUP은 나열한 항목을 단계적으로 줄여 소계와 총계를 구한다. CUBE는 모든 grouping 조합을 계산하고, GROUPING SETS는 필요한 조합만 명시한다. 집계 목적에 맞게 소계 구성을 선택할 수 있다.

관련 내용은 [group by clause](../../ko/part-03-sql-manual/20-sql-references-h-z.md#14659507262e5348)를 참조한다.

<a id="88b30486a017bfb8"></a>
### GROUP BY에서 SELECT 별칭 참조

GROUP BY의 grouping column reference에서 select list alias를 참조할 수 있게 되었다. SELECT 목록의 column에 지정한 별칭을 grouping key로 사용할 수 있다. 동일한 별칭이 여러 개이면 식별할 수 없고, 실제 column 이름과 별칭이 같으면 실제 column 참조가 우선한다.

```
SELECT COUNT(*), t1.c1 AS A1 FROM t1 GROUP BY A1;
```

관련 내용은 [group by clause](../../ko/part-03-sql-manual/20-sql-references-h-z.md#14659507262e5348)를 참조한다.

<a id="1a80dc90eab8eb2f"></a>
### PIVOT 절

Row 값을 column으로 변환하는 PIVOT 절이 추가되었다. FROM 절의 테이블 참조에 집계 함수, FOR에 pivot column, IN에 값 목록을 지정하여 cross table을 구성한다. 집계 함수는 중첩하여 사용할 수 없고, FOR column의 개수와 IN에 나열한 각 값 조합의 원소 개수가 같아야 한다.

관련 내용은 [pivot clause](../../ko/part-03-sql-manual/20-sql-references-h-z.md#fc4e37ea9e697ac1)를 참조한다.

<a id="d9088762fb32038e"></a>
### UNPIVOT 절

Column 값을 row로 변환하는 UNPIVOT 절이 추가되었다. IN에는 변환할 원본 column의 이름을 지정하고, 변환된 값을 저장할 column과 원본 column을 식별할 FOR column 이름을 정의한다. NULL 값을 결과에 포함하려면 INCLUDE NULLS를 지정한다. 이를 생략하면 기본적으로 EXCLUDE NULLS 로 동작한다.

관련 내용은 [unpivot clause](../../ko/part-03-sql-manual/20-sql-references-h-z.md#e4262e566d20f76e)를 참조한다.

<a id="9d637098e5ce7d96"></a>
### TABLESAMPLE 절

테이블에서 일부 row를 무작위로 추출하는 sample 절이 추가되었다. TABLESAMPLE에는 0보다 크고 100 이하인 샘플링 비율을 지정하며, PERCENT ROWS 또는 PERCENT PAGES 를 사용하여 샘플링 단위를 선택한다. 샘플링 단위를 생략하면 기본적으로 PERCENT ROWS가 적용된다. REPEATABLE(seed_value) 를 사용하여 seed 값을 지정할 수 있다. 이를 지정하지 않으면 실행할 때마다 샘플링 결과가 달라질 수 있다.

관련 내용은 [sample clause](../../ko/part-03-sql-manual/20-sql-references-h-z.md#778d71bbe6c00108)를 참조한다.

<a id="ea01a7f760507720"></a>
### 집계 함수의 FILTER

Aggregate function에 FILTER 기능이 추가되었다. 집계 함수 호출 뒤에 FILTER (WHERE condition)을 지정하면 해당 조건을 만족하는 값만 집계에 포함한다. 하나의 SELECT 문 안에서 각 집계 함수마다 서로 다른 조건을 지정할 수 있다.

```
SELECT COUNT(*), COUNT(*) FILTER (WHERE c1 > 1) FROM t1;
```

관련 내용은 [Aggregate Function](../../ko/part-03-sql-manual/11-sql-elements.md#67ffc000313e5858), [COUNT(*) FILTER](../../ko/part-03-sql-manual/17-built-in-function-references.md#9ba48f32b5d0883b)를 참조한다.

<a id="ffa7be4429dac4f0"></a>
### JSON 집계 함수의 FILTER

JSON aggregate constructor에 FILTER 기능이 추가되었다. JSON_ARRAYAGG 또는 JSON_OBJECTAGG 뒤에 FILTER (WHERE condition)을 지정하면 해당 조건을 만족하는 값만 배열 또는 객체의 집계에 포함된다. 집계 결과는 하나의 JSON 문자열 row 로 반환된다.

관련 내용은 [JSON aggregate Constructor](../../ko/part-03-sql-manual/11-sql-elements.md#900d89639c906cbd), [JSON_ARRAYAGG](../../ko/part-03-sql-manual/17-built-in-function-references.md#6a1307addaa8d032), [JSON_OBJECTAGG](../../ko/part-03-sql-manual/17-built-in-function-references.md#f2ed9f8209629cd7)를 참조한다.

<a id="e746f98573f62906"></a>
### Window 및 UNION ALL 실행 위치 힌트

SQL hint에 window hints와 union all driver hints가 추가되었다. Cluster query에서 window 기능 또는 UNION ALL 구문을 현재 서버에서 처리할지, 각 group의 서버에서 처리할지 지정한다. 해당 driver hint는 standalone 환경에서는 무시된다.

<a id="f67c8fb81ea5379b"></a>
| Hint 계열 | 현재 서버 | 각 group 서버 |
| --- | --- | --- |
| window hints | LOCAL_WINDOW | REMOTE_WINDOW |
| union all driver hints | LOCAL_UNION_ALL | REMOTE_UNION_ALL |

관련 내용은 [window hints](../../ko/part-03-sql-manual/15-sql-tuning.md#3a7dfb615d23e291), [union all driver hints](../../ko/part-03-sql-manual/15-sql-tuning.md#d5ea01efbed17bab)를 참조한다.

<a id="68910ccbf306485a"></a>
### ALTER SYSTEM CANCEL SESSION

세션에서 실행 중인 작업을 취소하는 ALTER SYSTEM CANCEL SESSION 문이 추가되었다. 취소할 대상의 session ID와 serial number를 지정하며, cluster database에서는 대상 member position도 지정할 수 있다. 이 문을 실행하려면 ALTER SYSTEM ON DATABASE 권한이 필요하다.

관련 내용은 [ALTER SYSTEM CANCEL SESSION](../../ko/part-03-sql-manual/18-sql-references-a-b.md#a9639e899e14c803)을 참조한다.

<a id="008ecc450edeb0a3"></a>
### SET ROLE

현재 세션의 role을 변경하는 SET ROLE role_name 문이 추가되었다. 현재 사용자에게 적용할 수 있는 role을 선택하거나 ACCESS CONTROL ON DATABASE 권한을 사용하여 role을 설정할 수 있다. SET ROLE NONE을 지정하면 current role 설정이 해제된다. 활성 트랜잭션 중에는 role을 변경할 수 없으며, 변경 후에는 설정된 current role을 기준으로 구문이 실행된다.

관련 내용은 [SET ROLE role_name](../../ko/part-03-sql-manual/20-sql-references-h-z.md#0af7a3d47e76664e)을 참조한다.

<a id="2aea470a4ff4c5be"></a>
### External Routine

사용자가 작성한 C 프로그램을 실행하는 External Routine 이 추가되었다. Shared library에 저장된 함수를 PSM routine에서 호출하며, external routine process인 gextproc가 library를 로딩·실행하고 결과를 PSM에 반환한다. Library 객체와 call specification을 구성하여 DBMS에서 외부 함수의 기능을 사용한다.

관련 내용은 [External Routine](../../ko/part-04-sql-psm-manual/28-external-routine.md#620a8dd903ce4629), [Call Specification](../../ko/part-04-sql-psm-manual/30-psm-language-element-references.md#1663813aaf9c3eb4)을 참조한다.

<a id="aca2816f1c8cd90c"></a>
### Trigger 객체

특정 테이블에서 DML이 수행될 때 자동으로 실행할 동작을 정의하는 trigger 객체가 추가되었다. PSM으로 작성한 동작을 INSERT·UPDATE·DELETE 이벤트와 연결하고, BEFORE/AFTER 시점 또는 ROW/STATEMENT 단위로 실행하도록 정의한다. 활성화된 트리거는 해당 이벤트가 발생하면 자동으로 실행되며, 명시적으로 호출할 수는 없다. 대상 테이블을 삭제하면 종속된 트리거도 함께 삭제된다.

관련 내용은 [Trigger 개요](../../ko/part-04-sql-psm-manual/29-trigger.md#5c78067dcf3e0b60), [CREATE TRIGGER](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#c36270132fc5138d)를 참조한다.

<a id="e4e4d48abb52b28a"></a>
### Call Specification

External C function과 PSM routine 정보를 대응시키는 call specification이 추가되었다. LANGUAGE C, LIBRARY, NAME, PARAMETER 를 사용하여 외부 함수의 이름과 인자·반환값의 데이터 타입을 매핑하고, PSM에서 호출한다. 이를 사용하려면 대상 library에 대한 EXECUTE 권한 또는 매뉴얼에 명시된 동등한 권한이 필요하다.

관련 내용은 [Call Specification](../../ko/part-04-sql-psm-manual/30-psm-language-element-references.md#1663813aaf9c3eb4)을 참조한다.

<a id="7915a1d737ae44fa"></a>
### Library 객체 DDL

Library 객체를 관리하는 CREATE LIBRARY와 DROP LIBRARY 문이 추가되었다. CREATE LIBRARY는 C 프로그램의 shared library 파일 경로를 스키마 객체 이름에 연결하며, OR REPLACE를 지정하면 기존 객체를 교체할 수 있다. DROP LIBRARY는 library 객체를 제거하고, IF EXISTS를 지정하여 해당 객체가 존재하는 경우에만 삭제하도록 할 수 있다.

관련 내용은 [CREATE LIBRARY](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#e6a29c79119e1af1), [DROP LIBRARY](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#11be420b5d5517c9)를 참조한다.

<a id="3e9703a51516b120"></a>
### Trigger 객체 DDL

Trigger 객체의 생성·삭제·재컴파일·활성화·이름 변경을 위한 다음 DDL이 추가되었다.

<a id="bdf2433c29e33cdc"></a>
| 구문 | 기능 |
| --- | --- |
| CREATE TRIGGER | DML 이벤트와 실행할 동작을 정의한다. |
| DROP TRIGGER | Trigger를 제거한다. |
| ALTER TRIGGER name COMPILE | Trigger를 재컴파일한다. |
| ALTER TRIGGER name ENABLE/DISABLE | Trigger의 활성화 여부를 변경한다. |
| ALTER TRIGGER name RENAME TO | Trigger 이름을 변경한다. |

관련 내용은 [CREATE TRIGGER](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#c36270132fc5138d), [DROP TRIGGER](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#405a8fa6b4a11ae3), [ALTER TRIGGER name COMPILE](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#7ef86e0333181a4e), [ALTER TRIGGER name ENABLE/DISABLE](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#f14d8e926a633165), [ALTER TRIGGER name RENAME TO](../../ko/part-04-sql-psm-manual/31-psm-sql-references.md#ae1a37f358aeb5db)를 참조한다.

## API 및 개발 환경

<a id="c063b3001f46287f"></a>
### JDBC commit_write_mode 연결 속성 추가

JDBC에 commit_write_mode 연결 속성이 추가되었다. 이 속성은 트랜잭션 완료 시 생성된 로그를 디스크의 로그 파일에 flush하는 방식을 지정한다. 이 값이 0이면 서버 설정을 따르고, 1이면 wait, 2이면 no wait를 의미한다. 기본값은 0이다.

관련 내용은 [JDBC: 연결 프로퍼티](../../ko/part-05-developer-manual/35-jdbc.md#ed8ac3d8d5f9ce8a)를 참조한다.

<a id="42fe503b51399aff"></a>
### gpec --parse 옵션 추가

Embedded SQL precompiler gpec에 --parse 옵션이 추가되었다. 이 옵션은 입력 소스의 파싱 수준을 지정하며, none은 실행에 필요한 최소한의 구조만 파싱하고, partial은 전처리에 필요한 범위까지 파싱한다. 기본값은 partial 이다. 예를 들어, gpec --parse=none sample.gc 와 같이 사용할 수 있다.

관련 내용은 [Embedded SQL: --parse](../../ko/part-05-developer-manual/36-embedded-sql.md#49761b68c953cb6c)를 참조한다.

<a id="a0f1bef08d8065cc"></a>
### Embedded SQL Dynamic SQL Method 4 지원

Embedded SQL에서 dynamic SQL method 4를 지원한다. 이 방식은 조회할 열의 개수·타입이나 매개변수 개수를 precompile 시점에 알 수 없는 SQL에 사용한다. ANSI SQL descriptor 방식과 SQLDA 방식을 제공하며, descriptor를 통해 실행 시점의 입력·출력 정보를 지정하여 PREPARE·EXECUTE 또는 커서 작업을 수행한다. 두 방식 모두 struct, SQL_CURSOR 타입과 VARCHAR 타입 배열을 이용한 array operation은 지원하지 않는다.

관련 내용은 [Embedded SQL: Method 4](../../ko/part-05-developer-manual/36-embedded-sql.md#d3f6958871fa8bc8)를 참조한다.

<a id="db8c6feb1bd31e0a"></a>
### PyDBC Python 3 타입 stub 제공

PyDBC Python 3 패키지에 pygoldilocks.pyi 타입 stub이 추가되었다. IDE와 정적 타입 검사 도구에서 사용할 수 있다.

관련 API는 [PyDBC: API Reference](../../ko/part-05-developer-manual/38-pydbc.md#ec81d02775010902)를 참조한다.

<a id="a2034477a23e62ad"></a>
### PyDBC Python 3 문자 codec 설정 지원

PyDBC Python 3에서 connection.setencoding()과 setdecoding()을 지원한다. setencoding(encoding, ctype=SQL_CHAR)은 SQL 문과 문자열 매개변수를 바이트로 변환할 때 사용할 codec을, setdecoding(sqltype, encoding, ctype=SQL_CHAR)은 문자 결과를 Python 문자열로 변환할 때 사용할 codec을 설정한다. 해당 설정 인자로는 SQL_CHAR만 사용할 수 있으며, wide character 타입은 지원하지 않는다. 설정은 해당 connection에 유지되며, SQL 실행이나 commit·rollback으로 초기화되지 않는다.

관련 내용은 [PyDBC: 문자 codec 설정](../../ko/part-05-developer-manual/38-pydbc.md#5645d68fe1c294ac)을 참조한다.

<a id="d12be1190cef60e0"></a>
### PyDBC Python 3 연결 진단·문자셋 조회·output converter 지원

PyDBC Python 3에서 connection.messages, character_set_name() 및 SQL 타입별 output converter를 지원한다. messages에는 연결 작업에서 발생한 DB-API warning이 저장된다. 이 목록은 다음 연결 작업이 시작될 때 초기화되므로, 각 작업 직후 확인해야 한다. character_set_name()은 현재 연결에 설정된 GOLDILOCKS 문자셋 이름을 반환한다.

add_output_converter(sqltype, func)로 변환 함수를 등록하면 해당 연결의 모든 cursor에 적용된다. 변환 함수에는 raw bytes 또는 SQL NULL을 나타내는 None이 전달되고, 함수의 반환값이 조회 결과의 행 값이 된다. 변환 함수의 등록 및 변경 사항은 다음 execute() 호출부터 반영된다. 자세한 내용은 [PyDBC: Output Converter](../../ko/part-05-developer-manual/38-pydbc.md#5645d68fe1c294ac)를 참조한다.

<a id="032496f0f45bfa25"></a>
### PyDBC connection.maxwrite 지원

대용량 문자·바이너리 매개변수를 처리하기 위한 connection.maxwrite를 지원한다. 이 속성은 매개변수를 직접 바인딩할지 SQLPutData로 전송할지 결정하는 기준 크기를 바이트 단위로 지정한다. 0을 지정하면 드라이버와 데이터 타입에 따른 기본 기준을 사용하며, 사용자 지정 값은 255 이상이어야 한다. 이 속성은 입력 데이터의 전송 방식만 변경하며, 데이터를 자르거나 조회 결과의 크기를 제한하지 않는다.

관련 내용은 [PyDBC: maxwrite](../../ko/part-05-developer-manual/38-pydbc.md#316bb46202e23005)를 참조한다.

<a id="5d9d18d1fd615104"></a>
### PyDBC cursor.nextset()을 통한 다중 result set 처리

Procedure가 반환하는 여러 result set을 cursor.nextset() 을 사용하여 순차적으로 처리할 수 있다. 현재 결과 집합의 행은 fetchone() 등의 fetch 함수로 읽고, nextset()을 호출하면 다음 결과 집합으로 이동한다. 다음 결과 집합이 있으면 True를, 더 이상 없으면 None을 반환한다.

관련 내용은 [PyDBC: nextset()](../../ko/part-05-developer-manual/38-pydbc.md#3da79da684bc42c6)을 참조한다.

<a id="aafb7682d013a920"></a>
### PyDBC procedureColumns() 메타데이터 조회 추가

PyDBC에 cursor.procedureColumns(procedure=None, catalog=None, schema=None)이 추가되었다. 이 method는 ODBC SQLProcedureColumns를 통해 procedure의 IN, OUT, INOUT 매개변수와 반환값·결과 열에 대한 메타데이터를 조회한다. 조회 결과에는 column_name, column_type, data_type, type_name, column_size, ordinal_position 등의 정보가 포함된다.

관련 내용은 [PyDBC: procedureColumns()](../../ko/part-05-developer-manual/38-pydbc.md#00a8ad785c1b5108)를 참조한다.

<a id="cbbab51febe8dc19"></a>
### PyDBC fetchval()·cursor iterator·statement cancel 지원

PyDBC에서 fetchval(), cursor iterator 및 statement cancel을 지원한다. fetchval()은 다음 행의 첫 번째 열 값을 반환하며, 다음 행이 없으면 None을 반환한다. cursor iterator는 결과 행을 하나씩 순차적으로 가져와 처리한다. cursor.cancel()은 해당 cursor에서 실행 중인 statement의 취소를 요청한다. 실제 취소 과정에서 예외가 발생할 수 있으므로 예외 처리를 마친 후 cursor를 재사용할 수 있는지 확인해야 한다.

관련 내용은 [PyDBC: fetchval()](../../ko/part-05-developer-manual/38-pydbc.md#27eb8c1db9ab866c)과 [cancel()](../../ko/part-05-developer-manual/38-pydbc.md#8d2e7ecf7507d431)을 참조한다.

### gloader/gloadernet의 APPEND INSERT 옵션

APPEND INSERT 방식으로 데이터를 로드하는 기능과 --merge, --skip_index_maintenance, --nologging 옵션이 추가되었다. import 작업에서 --merge EXTENT는 serial APPEND INSERT 방식으로, --merge SEGMENT는 PARALLEL APPEND INSERT 방식으로 데이터를 로드한다.

<a id="ba62f368abcc7304"></a>
| 옵션 | 사용 방법 |
| --- | --- |
| --skip_index_maintenance | --merge와 함께 사용한다. 인덱스를 갱신하지 않고 unusable 상태로 설정한다. 생략하면 DEFERRED_INDEX_MAINTENANCE 방식으로 수행한다. |
| --nologging | --merge SEGMENT와 함께 사용하여 NOLOGGING APPEND INSERT 방식으로 데이터를 로드한다. 생략하면 LOGGING 방식으로 수행한다. |

기존 --append 옵션은 로드 전 기존 데이터의 유지·삭제·TRUNCATE 여부를 지정하는 옵션이다. 새로 추가된 --merge 옵션과는 용도가 다르다.

관련 내용은 [gloader/gloadernet의 APPEND INSERT 옵션](../../ko/part-06-utility-manual/45-gloader-gloadernet-upload-download-tool.md#1740ac6239c20a32)을 참조한다.

## Replication

<a id="6b061e93640b1b2d"></a>
### CYCLONE을 이용하여 다른 DBMS로 데이터 이전

CYCLONE 을 통해 Oracle, DB2, MySQL, Tibero로 데이터를 이전하는 기능이 추가되었다. CYCLONE master는 원본 GOLDILOCKS의 redo log 에서 변경 내용을 분석하여 전송하고, slave는 ODBC를 이용하여 대상 DBMS에 변경 내용을 적용한다.

대상 DBMS에 따라 slave의 ORACLE_DRIVER, DB2_DRIVER, MYSQL_DRIVER, TIBERO_DRIVER에 해당 ODBC driver 파일의 경로를 지정한다. MySQL과 DB2의 경우 각각 MYSQL_DATABASE, DB2_DATABASE로 대상 database를 지정한다. SYNC 작업에는 master에 대응하는 해당 SYNC_ORACLE_DRIVER, SYNC_DB2_DRIVER, SYNC_MYSQL_DRIVER, SYNC_TIBERO_DRIVER 설정을 사용한다.

GOLDILOCKS와 대상 DBMS의 column 데이터 타입을 일치시켜야 한다. 다른 DBMS와 연동하는 경우 CYCLONE의 이중화 운영 중 DDL 처리 기능을 사용할 수 없다.

관련 내용은 [CYCLONE의 다른 DBMS로 데이터 이전](../../ko/part-07-replication/55-cyclone.md#f87b2f36314f159a)을 참조한다.

<a id="21aa7aea19aa7b33"></a>
### CYCLONE의 Heartbeat protocol 분리

CYCLONE의 heartbeat protocol이 data protocol과 분리되었다. 연결 유지 시간은 기존 설정인 HEARTBEAT_TIMEOUT 으로 지정한다. Master와 slave에서 사용할 수 있으며, network 단절이나 시스템 장애로 연결이 원활하지 않을 때 연결을 유지하는 최대 시간을 초 단위로 지정한다. 기본값은 30초이며, 최소값은 10초이다.

관련 내용은 [CYCLONE의 Heartbeat protocol 분리](../../ko/part-07-replication/55-cyclone.md#112e9713597fb4ff)를 참조한다.
